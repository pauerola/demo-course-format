Section 4 of 7

Can a computer learn to spot a fracture?

About 25 min · notebook cells 14–22 · 1 exercise

In short
  • Start from a model already trained on everyday photos, then fine-tune it on our X-rays.
  • device=0 trains on one GPU, and the GPU dashboard shows it working.
  • Compare accuracy with a simple baseline. For imbalanced data, look at recall.

4.1 The model

We’ll use YOLOv8n-cls, a small image classifier from the Ultralytics library. It’s a convolutional neural network, which picks out edges, textures and shapes in different parts of an image.

Training one from scratch would need far more than 4,000 images. Instead we use transfer learning: start from a model that has seen over a million everyday photos (ImageNet), then fine-tune it on X-rays.

Going deeper: why does transfer learning work on X-rays?

The early layers of a network learn general features such as edges and textures, which are useful for almost any image. Fine-tuning mostly adjusts the later layers to the new task, so far fewer examples are needed.

4.2 Training settings

Four settings control the run. You can change them in the exercise.

hpc-for-ai.ipynb
EPOCHS   = 50
IMG_SIZE = 512
BATCH    = 64
WORKERS  = 8
Setting What it means
EPOCHS Times the model sees every training image
IMG_SIZE Width and height of the square each image becomes
BATCH Images seen before the weights are updated
WORKERS CPU processes loading images so the GPU isn’t waiting

4.3 Train

Open the GPU dashboard first, then run the cell. Each epoch prints the loss and the validation accuracy.

hpc-for-ai.ipynb
model = YOLO(WEIGHTS)
model.train(
    data=str(SPLIT_DIR), epochs=EPOCHS, imgsz=IMG_SIZE,
    batch=BATCH, workers=WORKERS,
    device=0,   # one GPU
    project=str(RUNS_DIR), name="1gpu", seed=42,
)
What the other arguments do

project and name decide where results are saved (runs/1gpu in your scratch folder). seed makes the run repeatable.

4.4 How did training go?

Compare the two loss curves. If training loss keeps falling while validation loss rises, the model is overfitting. That’s why Ultralytics keeps the best epoch as best.pt.

4.5 Test the model

Classify every test image with best.pt and compare with the real labels. In the confusion matrix, the diagonal is correct. A missed fracture sits in the fractured row, not-fractured column.

real fractured found missed
real not false alarm correct
Reading the classification report
Score For the fractured class
Precision When it says “fractured”, how often is it right?
Recall What share of real fractures did it find?
F1 One score combining the two

4.6 Is that accuracy any good?

Most images show no fracture, so a “model” that always says not fractured would be right over 80% of the time and find nothing. Accuracy alone misleads on imbalanced data.

For triage, recall on the fractured class matters most. A missed fracture is worse than a false alarm a clinician can rule out.
